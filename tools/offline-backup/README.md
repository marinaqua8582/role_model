# 사용자 실행용 오프라인 셀 원본 백업

`start-backup.cmd`를 학교 PC에서 직접 더블클릭한다. 이미 설치된 Python 3.13/Tkinter와 Node.js만 사용하며 네트워크 요청은 하지 않는다. 브라우저의 키 입력 페이지를 사용하지 않는다.

1. 기존 KeePassXC의 64자리 16진수 백업 키를 로컬 숨김 입력란 두 칸에 직접 입력한다. 키를 명령 인수나 파일에 넣지 않는다.
2. 프로그램이 안내하는 표 하나씩 기존 운영 Sheets에서 전체 범위를 복사하고 ‘수집’을 누른다. Roster, Progress, Tests, Submissions를 같은 순서로 두 번 수집한다. 원본을 수정하거나 테스트 기록을 제외하지 않는다.
3. 필터/숨김 행·열, 추가 시트, 병합 셀이 있다면 중단한다. 원본 전체 선택은 사용자가 확인해야 한다. 두 번의 복사 사이 변경은 검출하지만, 전 시점의 원자적인 서버 스냅샷은 아니다. 수업 외 저장이 없는 시간에 실행한다.
4. 두 번의 셀 값·순서·형식 메타데이터 대조가 일치한 경우에만 암호화한다. 원본 표시값 TSV, HTML 원문, 가능한 Google 네이티브 클립보드 자료를 암호화 안에 보존한다. 날짜/수식의 원시 메타데이터 없이 일반 텍스트만 있으면 거절한다.
5. 지정 폴더 `C:\Users\user\롤모델챗봇_운영백업`에 AES-256-GCM 암호문만 생성한다. 메모리 복호화 후 전체 원본 비교, 디스크 재읽기 복호화 비교, 손상 태그·잘못된 키 거절을 확인한다. 전부 통과한 파일만 `.verified.enc`로 표시한다. 실패 시 `.pending.enc`가 남을 수 있으며 성공으로 처리하지 않는다. 파일을 자동 삭제하지 않는다.

키와 원본은 프로그램 자체의 평문 파일/로그로 기록하지 않는다. 로컬 프로세스 stdin 파이프로만 암호화 모듈에 전달한다. Windows 클립보드 기록·장치 간 동기화는 끄고 사용하며, 원본 캡처 직후 현재 클립보드를 비운다. 운영체제 스왑/프로세스 덤프까지 통제하는 제품은 아니다. 다른 앱에 원본을 붙여넣지 않는다.

성공 상태 파일 `work/offline-backup-status.json`에는 파일 경로, 암호문 해시, 표별 집계와 검증 여부만 기록한다. 학생별 해시/키/값은 기록하지 않는다. KeePassXC는 사용자가 직접 조작하며 이 도구가 읽거나 제어하지 않는다.

범위: 네 표의 선택된 셀 원본 보존. Google 파일의 버전 이력·공유 권한·댓글·첨부 파일 백업 또는 실제 원본 시트 복원 시험은 아니다. 원본 시트/GAS 수정, DB 이관, 운영 설정/배포는 하지 않는다. 백업 완료 후 별도 승인 전까지 원본과 암호문을 유지한다.

## 합성 검증 (2026-10-15)

신규 도구 전용 unittest 10개 통과. 다중행 JSON, 빈 셀, 수식 메타데이터/원문 보존, 잘못된 표/일반 텍스트/병합 셀/불일치 거절, 소스 변경 검출, 네이티브 포맷 파싱, AES 파일 재읽기·복호화·태그/다른 키 거절, 키 불일치 시 파일 미생성을 확인했다. 최초 실행은 샌드박스 임시 폴더 ACL로 2개 오류였으며 합성 임시 경로를 작업 공간으로 바꾸어 10개 모두 통과했다. 실제 원본 복사·사용자 입력·백업 실행은 아직 미검증이다. 기존 성능/UI 시험은 반복하지 않았다.
