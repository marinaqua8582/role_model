# 운영 전환 1단계 구현 및 검증

기준: f950fce 및 이전 91bf552 자료 보존. 실제 학생/운영 연결/운영 GAS/main/production/유료 설정 변경 없음.

## 구현된 실행 경로

- `createRegisteredService` / `createRegisteredHttp`: fixture 25명 고정 검사 대신 등록 명단의 학년·반·번호·이름으로 로그인. NFC·공백 정규화, `class`/`classNo`/`classNum` 호환, 본인 전체 Google ID, 서버 HMAC 세션/DB 세션 검증 유지. HTTP payload의 admin=true는 권한을 부여하지 않는다. 서버가 기존 관리자 서명을 검증해 전달한 로그인 시각만 신뢰한다.
- 운영 정책 adapter는 의존성을 주입하는 준비 코드다. 현 production 환경의 실행 차단은 유지했다. HTTP 경로를 운영 DB에 연결하는 배포 설정은 이 승인에 포함되지 않아 적용하지 않았다. openDatabase는 기본 합성 모드의 제한을 유지하고 명시적 registered 모드에만 role_model_operating 스키마를 허용하는 준비 경로를 추가했다. 해당 운영 스키마나 연결은 생성·접속하지 않았다. 다음 운영 설정 승인 때 대상 스키마·DB 역할·서버 라우팅을 검증하여 연결해야 한다.
- `planRegisteredMigration`: 인원/학급을 fixture로 고정하지 않고 Roster 신원을 사용한다. Progress/Tests/Submissions/Counseling의 원본 행·미지 열은 archive에 보존. 키 정규화/고아 행/상충 중복/JSON 오류/신원 충돌은 자동 삭제·해결하지 않고 중단한다. 같은 중복 원본은 archive에 남긴다. Counseling 시각 충돌과 빈 제출값 보호를 유지하고, STEP1~11 JSON 및 누락 Tests/Counseling 행의 기존 중첩 데이터 보존을 보강했다.
- `applyRegisteredMigration` / `reconcileRegistered`: 원본 계획 재계산 및 위조 검사, 목적지 사용 여부/동일 신원 검사, 전체 원자 적용과 sourceDigest 멱등 처리, 학생별 전체 문서·버전 대조. 원래 최신 자료가 있는 목적지를 덮지 않는다.
- `exportRegisteredSnapshot` / `restoreRegisteredSnapshot`: 답안·버전·전체 receipt를 한 일관된 snapshot으로 저장/복원. pending/unknown/cancelled도 삭제하지 않는다. 복구는 비어 있는 목적지에서만 실행하고 기존 답안 덮어쓰기를 거절한다. 원본 표 archive도 암호화 백업에 함께 보존한다.

## 쓰기 차단 및 순서

- PostgreSQL `synthetic_control`은 영속 closed/epoch/openedAt를 보관한다. 학생 저장·검사·수정·최종·상담 제출·취소·명단 변경·receipt 정리는 공유 advisory transaction lock을 획득한 뒤 상태를 검사한다. 공유 잠금은 서로 다른 학생 쓰기를 직렬화하지 않는다. exclusive lock을 사용하는 `setMaintenance`는 이미 승인된 쓰기 commit을 기다린 뒤 차단을 기록한다. timeout/잠금 오류 때 차단 완료라고 표시하지 않는다.
- 잠금 순서는 admission 공유 잠금 → 학생 행, 전환/이관/복구는 exclusive admission → 메타/학생 행이다. 완료 상태 뒤 대기 요청이 도착해도 닫힌 상태를 다시 검사해 거절한다. 재개 후 학생의 서명된 epoch와 관리자 서명 로그인 시각으로 오래된 요청을 거절한다. 서버 상태 확인은 계속 가능하고 저장 자동 재시도는 추가하지 않았다.
- GAS 소스/생성 템플릿 동일 변경: editor-only `closeWritesForCutover`, `getCutoverWriteStatus`, `reopenWritesAfterRollback`. 기존 ScriptLock을 잡은 뒤 writes를 검사하고 닫힐 때 flush 후 완료한다. 지연 학생/명단 요청은 epoch·발행 시각을 검사한다. 닫힌 상태의 미확인 receipt 조회는 unknown을 반환하며 새 취소 receipt를 쓰지 않는다. 정리 트리거도 잠금 안에서 다시 차단을 확인한다.
- GAS 재개 후 학생 클라이언트는 로그인 응답의 maintenanceEpoch를 보관·전송한다. 관리자 서버는 `CUTOVER_CONTROLS_ENABLED=true`일 때 GAS 상태를 확인하고 검증된 관리자 로그인 시각으로 오래된 명단 요청을 막는다. 이 설정은 실제 운영에 적용하지 않았다. 관리자 재로그인과 학생 재로그인을 완료하기 전 오래된 화면 저장을 허용하지 않는다.
- 실제 절차: 양쪽 close → 진행 중 쓰기 drain 성공 → 두 snapshot 동일성 확인 → 원본 archive 포함 AES-256-GCM 암호화/복호화 검증 → 사용 전 목적지 이관 → 문서·버전 대조 → 로그인/학생·관리자 읽기 일치 → 새 DB만 open. 기존 GAS는 계속 closed. 새 답안 후 실패 시 다시 close → 최신 snapshot → 빈 PG 복구 대상 → 전체 값 대조 → DB 연결 복구. Sheets 되쓰기/원본 초기화 없음.

## 실행한 검증

- 새 자동 검사8개: 등록 신원/본인 ID/타인 접근, 전체 쓰기 차단·읽기/receipt 조회·이전 세션 거절·신규 세션 저장, 암호화/이관/대조/새 제출/복구, 상충 중복·고아·누락·JSON·신원 오류, 일부 실패 원자 rollback/위조 계획/불안정 snapshot, GAS 전체 쓰기 거절/지연 요청, HTTP 관리자 위조 및 제외·재등록, 중첩 데이터·정리 보존.
- 전체 회귀 **248/248 통과**, lint 및 기본 `npm run build` 성공. 기존240개를 삭제/완화하지 않았다. 처음 sandbox 전체 검사는 로컬 HTTP EACCES와 GS 줄바꿈 불일치로 실패했다. 줄바꿈을 기존 export 도구로 바로잡고 정상 실행 환경에서 전체 검사를 다시 실행해 통과했다. 실패를 성공으로 처리하지 않았다. 마지막 관리자 읽기 허용 조건 조정 뒤 해당 runtime/새 검사10개도 통과했다.
- 실제 Supabase PostgreSQL: `cutover-pg-rehearsal.json`에서 합성25명 이관/대조, 접수 쓰기의 공유 잠금 중 exclusive close가 기다리는 것, 새 저장 차단/재개 후 이전 서명 세션 차단, 새 최종 제출·중복 요청 replay, 재로그인=관리자 문서, 최신 답안·버전·pending/unknown/cancelled receipt 복구를 확인했다. 기존 synthetic 스키마는 변경하지 않고 같은 승인된 무료 프로젝트 안의 별도 리허설 스키마를 사용했다. 새 서비스/프로젝트·결제 없음.
- GAS는 로컬 emulation으로 검증했고 원격 테스트 GAS나 운영 GAS에 배포하지 않았다. 이번 adapter의 브라우저 Preview/실제 GAS end-to-end 전환은 미실행이다. 기존 모바일/학생·학급 PDF는 UI 배치가 변하지 않아 재사용했다. 기존25명 응답시간은 이전 배포의 수치다. 새 admission 조회가 추가된 후보에서 p95 목표를 실측했다고 주장하지 않는다. 전체 회귀의 로컬25명 시험은 외부 Vercel 실측이 아니다.

## 실행 방법과 다음 승인

- 로컬: `node --test tests/cutover.test.cjs`, `npm test`, `npm run lint`, `npm run build`.
- 외부 합성 리허설: `CUTOVER_REHEARSAL_CONFIRM=SYNTHETIC_ONLY`, `CUTOVER_PRIVATE_FILE`을 비공개 JSON 경로로 지정해 `node transactional/rehearse-cutover.mjs`. 비밀값을 명령줄에 직접 넣지 않는다. 이 도구는 승인된 합성 프로젝트 이외의 DB 연결을 거절한다. 새 리허설 스키마를 만들므로 이미 완료한 리허설을 이유 없이 반복하지 않는다.
- 실제 운영 인증/명단·헤더 및 추가 인증 계층은 아직 접근하지 않아 완전 호환을 선언하지 않는다. 운영 Free 백업·일시 정지 위험, Sheets 되쓰기 미검증, 학교 실물 PC/모바일 확인은 이전 절차대로 남아 있다.
- 합성 Preview/테스트 GAS 연결 검증은 이번 승인 범위지만 이번 실행에서는 수행하지 않았다. 다음 별도 승인 대상은 실제 자료 읽기·비공개 백업으로 인증/헤더/충돌 대조, 학교가 승인한 운영 DB 스키마·권한/접속 설정이다. 실제 운영 접속 설정, 이관, main 및 production 배포는 각각 별도 승인 필요. 이번 개발 승인만으로 실행하지 않는다.
- 원본은 수정하지 않지만 실제 자료 읽기/백업도 개인정보 처리에 해당한다. 그 승인을 받기 전에는 운영 자료를 수집하지 않는다. 이관 중에는 수업 쓰기 중단이 필요하고, 대조 실패 시 전환하지 않는다. 새 저장이 생긴 뒤 과거 Sheets로 바로 되돌리면 답안을 잃을 수 있어 최신 PG 복구를 먼저 사용한다.
