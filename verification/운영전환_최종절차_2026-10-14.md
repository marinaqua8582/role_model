# 운영 전환 최종 절차 — 승인 전 실행 금지

기준 보존 commit: 91bf552. 현재 판정: 합성 검증 통과 / 실제 운영 전환 보류.
이 문서는 실행 계획이며 운영 환경에 유지보수 모드나 백업을 적용했다는 뜻이 아니다.

## 확인된 호환성과 남은 승인 단계

- 소스의 GAS 로그인은 학년·반·번호와 NFC/공백 정규화한 이름을 대조한다. PostgreSQL도 같은 핵심 조건이며 본인의 전체 Google ID와 서버 발급 세션을 반환한다. 현재 검토한 코드에는 별도 학생 인증 코드 입력 비교가 없다. 실제 운영 배포에 다른 인증 계층/코드가 있는지는 아직 읽지 않았으므로 동일하다고 확정하지 않는다. 승인 후 운영 배포 코드·인증 설정을 비공개로 대조하며 불일치 시 중단한다. 기존 토큰을 새 저장소에 그대로 사용하지 않고 동일 로그인 화면으로 다시 로그인한다.
- studentKey는 학년-반-번호의 정규 숫자로 유지. 같은 키의 이름/Google ID 충돌은 자동 연결하지 않는다. 등록 목록 제외는 답안 삭제가 아니며 동일 신원 재등록 시 복원한다.
- 중요 제한: store/runtime/openDatabase는 합성 환경·스키마만 허용한다. migration의 owner는 fixture 25명만 허용한다. registeredIdentity는 분리된 검사 함수일 뿐 운영 adapter가 아니다. 실제 명단/인증 정책을 적용하는 운영용 adapter와 범용 이관 경로는 아직 구현·검증되지 않았다. 합성 제한을 단순 제거하거나 환경변수만 변경해서 배포하지 않는다. 이 준비 작업에서는 제한을 유지한다.

## 이관 및 대조 규칙

1. 승인 후 원본 5개 표(Roster/Progress/Tests/Submissions/Counseling)의 헤더·원래 행 순서·빈 셀·날짜·JSON·알 수 없는 열을 비공개 원본으로 보존한다. Counseling 표가 없으면 없는 사실도 기록한다. 인증 설정과 운영 GAS/배포 버전은 별도 비밀 백업. 공개 로그/Git에는 개수와 성공 여부만 남긴다.
2. 원본 전체 SHA-256, 표별 행 수, 정규 studentKey 집합, 학생별 원본/변환 문서 해시를 비공개 manifest로 만든다. 개인 식별 해시도 공개 저장소에 올리지 않는다.
3. Roster를 신원 원본으로 삼고 키만 있는 Tests도 엄격히 연결한다. Roster 없는 답안은 삭제하지 않고 미해결 목록에 보존하고 전환을 중단한다. 표 중복은 같은 값도 원본에 남긴다. 상충 중복/키·신원 충돌/JSON 실패는 임의 선택하지 않는다.
4. Progress의 STEP 데이터/진행 상태, Tests 결과·step8, Submissions 최종 제출·step10, Counseling 답변·성찰·step11을 모두 대조한다. 빈 제출 열로 채워진 답안을 지우지 않는다. Counseling과 제출 충돌은 신뢰 가능한 서로 다른 시각으로만 선택하며 시각 부재/동률은 교사 확인 후 해결한다. 원래 양쪽 값은 계속 보존한다.
5. 보존과 화면 복원을 구분한다. 원본 archive만 남고 화면에서 사용하지 못하는 열은 완료로 간주하지 않는다. 모든 STEP 필드의 변환표와 학생/관리자 복원 문서가 일치해야 한다. 현재 합성 필드 리허설은 통과했지만 실제 헤더별 변환표는 승인 후 확정한다.
6. 사용하지 않은 목적지에 한 트랜잭션으로 적용하고 동일 sourceDigest 재실행은 멱등 처리한다. 기존 답안이 있는 목적지는 덮어쓰지 않는다. 실패 시 부분 답안/receipt가 없어야 한다.
7. 원본 대비 학생 집합·표 행 수·최종 완료 수·각 STEP/검사/상담/제출 값·전체 Google ID·변환 문서 해시 일치를 비공개로 확인한다. 값의 의미를 바꾸는 정규화는 승인된 규칙만 허용한다. 불일치 1건이라도 새 저장을 열지 않는다.

## 전환 순서와 승인 구분

1. [코드 준비 승인 필요] 운영 adapter/인증 호환, 아래 서버 쓰기 차단 장치를 합성 환경에서 구현·검증한다. 지금은 미구현이며 이 단계 통과 전 실제 전환 승인 요청을 하지 않는다.
2. [실제 자료 읽기·백업 승인] 수업 밖 전환 시간을 정한다. 운영 코드/환경의 비공개 백업과 되돌릴 Vercel/GAS 버전을 확보한다. 연결 정보는 채팅/로그로 출력하지 않는다.
3. [운영 GAS 수정 승인] 모든 쓰기(저장/검사/수정/최종·상담 제출/초기화/명단 변경)를 GAS 잠금 획득 후 실제 쓰기 전에 서버 유지보수 상태로 차단한다. 기존 세션·직접 GAS 호출·이전 Vercel 배포도 막혀야 한다. 로그인·읽기·receipt 확인만 허용한다. 학생에게 새 입력 중지 및 미저장 내용 보관을 안내한다. UI 차단만으로 대체하지 않는다.
4. 차단 확인 후 이미 실행 중인 GAS 작업이 모두 종료될 때까지 기다린다. 잠금 왕복 확인만으로 아직 대기 중인 호출 종료를 단정하지 않는다. 진행/미확인 receipt와 실행 기록을 정리하고, 확인 불가능한 요청이 있으면 전환 중단. 원본을 시간 간격을 두고 두 번 읽어 해시/행 수가 안정적임을 확인한다. 운영 백업은 이 시점에 다시 확정한다.
5. [실제 이관·운영 DB 설정 승인] 합성 데이터와 분리된 운영 저장 영역/접근 역할을 확정하고 원본을 변경하지 않는 이관·대조를 실행한다. 테스트 비밀값과 합성 계정은 운영에 복사하지 않는다. 유지보수 중 새 PostgreSQL 저장도 차단한다.
6. [main·production 배포 승인] 대조 성공 후 검증된 소스/운영 전용 설정을 반영한다. STAGING/TEST/PERF API 비활성, LOGIN_BATCH_READS 비활성, 테스트 프로젝트 연결 없음 확인. 관리자/학생 읽기 복원과 상태를 먼저 확인한다. 기존 Sheets/GAS 쓰기 차단은 유지해 이중 저장을 막는다.
7. 새 PostgreSQL 서버의 쓰기만 열고 실제 수업을 시작한다. 브라우저 저장 완료는 영속 commit 뒤 응답 성공일 때만 표시. 실패/불명확 요청은 상태 확인하고 무조건 재전송하지 않는다. 옛 GAS는 읽기 전용 보존한다.

## 백업·복구 확정 정책

- 전환 전: 원본 5개 표 + 코드/배포 버전 + 비공개 설정 목록 + 대조 manifest를 암호화해 학교 승인 위치 두 곳에 보관. 복호화 키는 백업과 분리한다. 인증 정보는 공개 보고서에 포함하지 않는다.
- 새 저장을 열기 전 실패: 목적지를 격리하고 기존 배포로 되돌린 뒤 원본 안정성 확인 후 GAS 쓰기를 다시 연다. 이때 새 답안이 없다는 확인이 필수다.
- 새 저장을 연 뒤 실패: 양쪽 쓰기를 먼저 멈추고 PostgreSQL의 최신 답안/버전/전체 receipt(처리 중·불명확 포함)를 추가 백업한다. 현재 스냅샷을 빈 PostgreSQL 복구 대상에 복원한 후 문서/버전/receipt 일치 확인하여 앱 연결을 복구한다. 최신 답안을 과거 스냅샷으로 덮지 않는다. 학생 세션은 다시 발급한다.
- 기존 Sheets로 단순 연결 복귀 금지: 전환 이후 새 답안을 잃을 수 있다. Sheets 되쓰기 도구는 미검증이므로 우선 최신 PostgreSQL 복구를 사용한다. 복구 실패 시 유지보수 상태로 남기고 학생에게 작성 중지 안내, 원본·새 백업 모두 보존한다.
- 수업 직전/직후 및 명단 변경 전 암호화 백업과 정기 복구 리허설을 담당자가 확인한다. Free 백업만으로 서버 장애 직전 마지막 저장까지 무손실 복구는 보장되지 않는다. 수업 중 DB 자체 손실에 대한 무손실 요구는 추가 내구성/백업 방식 승인 전 충족하지 못한다.

## Free 수업 운영 방안 — 2026-10-14 공식 문서 확인

- Free는 DB 500MB, 자동 백업/PITR 미포함. 낮은 활동이 7일 지속되면 일시 정지할 수 있다. 정기 오프사이트 export를 공식 문서가 권장한다. 유료 설정은 실행하지 않았다.
- 수업 전날 대시보드 상태·용량·연결과 비공개 백업을 확인한다. 당일 수업 30분 전 재개 필요 여부를 확인하고 준비된 합성 검증 또는 허용된 운영 확인으로 로그인/읽기 상태를 점검한다. 방학 후 특히 재개 확인이 필요하다. 충분한 일일 이용도 일시 정지 제외를 보장하지 않는다.
- 수업 중 오류에는 반복 저장 대신 receipt 확인, 불확실 상태 안내, 작성 내용 보관 후 교사에게 알림. 장애가 지속되면 수업 저장 중지. 교사는 준비한 오프라인 활동으로 진행한다. Free의 중단 없는 50분 수업이나 장애 무손실 복구는 보증할 수 없다.
- 연결 한도는 해당 프로젝트 Compute/Pooler 화면에서 승인 후 확인한다. 가격표의 Realtime 동시 연결 200은 PostgreSQL 연결 한도로 사용하지 않는다. 25명 합성 실측 통과가 실제 운영 크기·용량 확인을 대체하지 않는다.
