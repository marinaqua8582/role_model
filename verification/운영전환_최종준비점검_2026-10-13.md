## 운영을 막는 확인된 코드 차이

1. `transactional/store.mjs`의 fixture/getRosterOptions/인증은 고정 합성25명 전용이다. 실제 등록 명단을 사용하지 않는다. `assertSyntheticEnvironment`는 VERCEL_ENV=production을 명시적으로 거절한다. 안전 장치를 단순 해제해서 운영에 배포하면 안 된다.
2. 새 DB 관리자 경로는 checkAdminConfig/getAdminDashboard/getStudentDetail만 구현하고, 명단 업로드·추가·삭제는 SCOPE로 거절한다. 기존 화면 버튼이 존재하는 것과 기능이 운영에 보존된 것은 다르다.
3. 이관 도구는 합성25명 신원만 허용한다. 실제 GAS `schemas_()`의 Tests는 studentKey와 검사 결과만 있고 이름·GoogleID가 없을 수 있다. 이 형식의 합성 행을 생성해 확인했으며 현재 이관기는 거절했다. 실패를 숨기거나 신원 검증을 해제하지 않았다.
4. GAS에는 별도 Counseling 표가 있지만 이관기가 활성 문서로 조립하는 표는 Roster/Progress/Tests/Submissions다. Counseling 합성 표의 원본은 legacyArchive에 남지만 학생/관리자 활성 답안으로 복원되지 않았다. 원본 백업 보존만으로 상담 답안 복원을 통과 처리할 수 없다.
5. 현재 복구는 미사용 합성 DB에 복원하는 방식이다. 전환 후 새 답안을 보존하면서 기존 Sheets 방식으로 되돌리는 실행 도구와 운영 호환 검증은 완료되지 않았다. 옛 Sheets에 덮어써 되돌리는 방법은 금지한다.

위 문제 때문에 현 후보를 그대로 main에 합치거나 운영 환경변수를 바꾸는 것은 허용할 수 없다. 운영 지원 명단·기존 관리자 변경 기능·실제 GAS 형식 이관·전환 후 답안 보존 복귀의 최소 호환 작업과 합성 회귀 검증이 필요하다. 실제 자료 접근 승인이 이 코드 차이를 해결해 주지는 않는다.

[Vercel Hobby](https://vercel.com/docs/plans/hobby)는 사용 한도와 비상업 개인 용도 조건이 있다. 학교 운영 용도 적합성 및 실제 운영 프로젝트 잔여 한도는 운영 접근 승인 후 별도 확인해야 한다. [Supabase 상태](https://status.supabase.com/) 확인 시 Functions·Logging/Observability 장애 공지가 있었다. 직접 PostgreSQL 저장 장애로 단정하지 않으며 이번 DB 연결은 성공했다. 수업 전 공급자 상태 확인이 필요하다.

운영 전환 후 사용할 기본 대응: 저장 완료 응답 전에는 완료로 안내하지 않음. 불명확하면 동일 저장 재전송 대신 receipt 확인. 해결되지 않으면 입력을 유지한 채 교사에게 알리고 쓰기/전환 작업을 중단. 복구 시 새 DB 쓰기를 먼저 중지하고 최신 문서/버전/receipt를 추가 백업한 뒤 검증된 복구 대상에서 재개. 이전 GAS/Vercel 배포와 원본 Sheets는 보존.

## 승인과 교사 조작 순서

현재 필요한 조작은 합성 Preview의 관리자 로그인뿐이며 비밀번호를 채팅에 보내지 않는다. 관리자 화면 검사 완료 후에도 위 코드 호환성 문제가 남으면 운영 배포 승인 요청은 보류한다.

최종 승인 항목은 분리해야 한다: (1) 실제 자료 읽기·비공개 암호화 백업(원본 무변경), (2) 분리된 운영 DB 설정·비밀값 적용 및 검증된 이관, (3) 수업 외 유지보수 시간의 쓰기 일시 중지·최종 차이 이관·main 병합·production 전환, (4) 문제 시 새 답안 추가 백업 후 복구. 유료 전환은 이 승인들과 별도다. 아직 어느 항목도 실행하지 않았다.
