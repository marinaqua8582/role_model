## 실제 시험 결과

브라우저 1명: 로그인 → STEP 1 저장 성공 응답 → 로그아웃 → 재로그인에서 STEP 2/롤모델 복원 → STEP 2~9 저장 → STEP 10 새 최종 제출 완료를 실제 클릭으로 확인. STEP 7 본인의 전체 synthetic ID만 표시. Gem/상담 내용은 합성 입력이며 외부 Gemini 서비스 제작·품질 시험은 아님.

25명 동시 API 시험은 실제 Preview와 PostgreSQL로 1회 완주했다. 먼저 관리자 사전 인증에 실패한 실행은 가려진 환경변수 값을 잘못 사용한 시험 설정 문제로, phases={}이고 학생 저장 요청 전 중단했다. 기존 합성 관리자 비공개값으로 인증 성공 후 시험을 실행했다. 실패 기록은 별도 보존한다.

lockWaitMs는 BEGIN/SET/학생행 FOR UPDATE 왕복과 transaction pooler 대기를 포함하므로 순수 동일 학생 잠금 대기라고 단정하지 않는다. 전역 ScriptLock은 새 저장 경로에서 사용하지 않으며 학생별 DB 행 잠금·버전 CAS를 사용한다. lockHeldMs는 행 획득 후 COMMIT까지, dbRead/dbWrite는 SQL 왕복 포함이다. Vercel 빌드 위치는 iad1로 확인했으나 DB는 서울이다.

추가 실제 클라이언트 코드(브라우저 대신 Node VM)와 원격 Preview 시험: 서버 COMMIT 응답을 받은 뒤 클라이언트에 전달하지 않고 오류를 주입했다. 쓰기 요청은 정확히 1회, 불명확 상태에서 새 쓰기 차단, receipt 조회로 완료 확인, 자동 재전송 0. 두 세션의 오래된 버전 저장 거절과 최신 답안 보존 확인. 실제 전송 중 인터넷 단절이나 COMMIT 직전 서버 강제 종료까지 시험한 것은 아니다.

## 남은 운영 전환 작업 및 승인

이번 합성 1회 저장 p95 최댓값 3.810초/전체 최대 3.846초로 새 목표 p95≤5초·최대≤10초를 충족했다. 장시간 수업·실제 자료·반복 cold start 성능 보장은 아니다. 예전 GAS 최대 57~64초와 비교해 구조 효과가 보이지만 서로 다른 환경/작업 부하라 정확한 개선율로 환산하지 않는다. 기존 Google 콘텐츠 404의 원인을 고친 것이 아니라 새 로그인에서 GAS 리디렉션을 제거했다.

운영 승인 전 필요: 개인정보/지역/무료 중지·한도 및 운영 서비스 결정, 실제 학생 로그인 인증정책과 필드 호환 추가 검토, 비공개 운영 백업·읽기 전용 export·키/신원/답안 대조, 유지보수 중 쓰기 중지, 전환 후 새 답안까지 보존한 복구 리허설, 운영용 receipt/session 유지보수 스케줄. 합성 이관기는 실제 자료를 거절하므로 그대로 운영 이관에 사용할 수 없다. 실제 학생 자료 이관·운영 서비스 설정·main 병합·production 배포는 별도 최종 승인 필요. 관리자 UI 실제 클릭은 미실행이고 관리자 API 조회 일치만 실측했다. Free는 자동 백업이 없으므로 실제 운영 백업 정책도 별도 마련해야 한다.

현재 직접 입력 차단 사항은 없음. 운영 전환 승인 전까지 합성 Preview에서만 유지한다.
