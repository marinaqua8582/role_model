# 합성 전용 학생별 트랜잭션 구현 검증 — 2026-10-12

## 실제로 구현한 것

기준: 원격 integration d424c2160472d9b9febe3415111f483db55fcd8f 확인, 로컬 57fbed 기반의 깨끗한 작업 상태에서 시작했다. 기존 binary 이미지·history bundle 업로드는 별도 미완료 과제로 남겼다. main·운영·실제 학생 자료는 접근/변경하지 않았다.

`transactional/store.mjs`: SQLite 디스크 참조 구현과 PostgreSQL 학생 행 잠금 어댑터, 학생 단위 문서, 버전 CAS, 고유 receipt, 취소 tombstone, 세션 검증, 합성 신원 제한. COMMIT 이후에만 성공 응답한다. DB 읽기/쓰기/COMMIT·잠금 대기/보유·풀 대기·전체 시간을 구분한다. SQLite는 전역 DB writer이므로 이 결과를 PostgreSQL 학생별 병렬 처리의 실측이라고 부르지 않는다.

`api/gas-proxy.ts`, `api/_lib.ts`, `transactional/runtime.mjs`: 명시적인 합성 플래그에서 학생/관리자 같은 DB를 사용한다. 로그인은 GAS 콘텐츠 리디렉션을 거치지 않는다. production에서는 새 경로가 거절된다. 플래그가 없으면 기존 GAS를 사용한다. 오류 원문·토큰·신원·답안은 로그로 출력하지 않는다.

`src/api/client.ts`: 새 backend에서만 expectedVersion을 전송하고 읽기/저장/receipt 응답 버전을 반영한다. 확정된 충돌·취소·만료는 실패로 표시하고, 불명확한 결과는 보류하여 receipt 확인 전 재저장을 막는다. 기존 UI 및 GAS 정책은 유지했다.

`transactional/setup.mjs`, `local-server.mjs`, `run-staging.mjs`: 명시적인 합성 초기화, 실제 localhost API, 보호된 외부 Preview 시험 실행 도구. 외부 도구는 작성했지만 실행하지 않았다.

`transactional/recovery.mjs`: 합성 문서/버전/receipt 백업과 미사용 DB 복구. 기존 답안이 있는 목적지는 거절한다. 운영 이관기는 아니다. 운영 비공개 백업·기존 답안 호환·전환 후 답안까지 보존하는 복구 절차는 [설명서](../transactional/README.md)에 정리했다.

기존 GAS 두 소스·인증 코드·본인 전체 Google ID·batch 기본 비활성·중복 행 방지·staging 시험 토큰·5분 GAS trigger는 변경하지 않았다. PostgreSQL 스키마는 비공개이며 합성 25명 외 자료가 있으면 거절한다. 자동 배포 차단 설정은 그대로다.

정상 작업 성공률 100%, timeout/응답 실패/답안 유실/중복 학생 문서/오학생 갱신/타인 Google ID 노출 0. Progress/Tests/Submissions는 한 학생 문서 내부이므로 물리적인 Sheets 중복 행 검사는 해당 없음; DB 고유키·문서 수 25·각 영역 답안 일치를 검증했다. 부정 요청은 의도대로 거절했고 정상 성공률에 포함하지 않았다.

실제 클라이언트 TypeScript 코드를 VM에서 실행하여 HTTP API에 연결했다. 25명 단계 저장·재로그인·새 최종 제출·복원 일치, STEP7 React 출력에서 본인 전체 ID만 표시, 응답 유실 시 실패/미확인 표시·추가 저장 차단·receipt 완료 확인 후 해제, 두 화면 충돌 후 명시적 재조회로 복구를 검증했다. 브라우저 실제 클릭 시험은 아직 하지 않았다.

같은 ID 10회 동시 요청은 버전 1회 증가, 다른 내용 ID 재사용 차단, stale 버전 거절, 취소 후 지연 저장 미반영, 완료 후 취소가 완료 기록을 바꾸지 않음, receipt 쓰기 실패 시 문서까지 rollback, 만료 receipt allowlist 보호, 백업/복구가 전환 후 최신 답안과 receipt를 보존하고 덮어쓰기를 거절함을 확인했다.

추가 검사 과정에서 로컬 harness 오류 응답의 backend 표시 누락을 발견했다. 오래된 저장은 DB에서 거절되었으나 클라이언트의 미확인 상태가 해제되지 않았다. 실제 runtime 계약과 동일하게 고친 뒤 전체 재검사를 통과했다. 이 실패를 숨기거나 부하 시험으로 통과시킨 것이 아니다.

## 운영 전환까지 남은 작업

PostgreSQL 실서버 실행·TLS/권한·행 잠금 병렬성·풀 대기·cold start·Vercel 다중 인스턴스·실제 외부 25명 시험은 미검증이다. 실제 브라우저 전체 경로, 원격 응답 유실/접속 단절/COMMIT 중 강제 종료도 추가 확인해야 한다. 기존 GAS의 콘텐츠 404는 기존 경로에서 해결했다고 주장하지 않는다. 새 경로는 그 의존성 자체를 제거했다.

실제 자료 이관은 설계/절차만 준비했으며 실제 Sheets 이관기·비공개 암호화 백업·복구 델타 병합기는 별도 승인 후 구현해야 한다. 합성용 신원 고정 코드를 운영에 그대로 사용할 수 없다. 외부 staging에서 목표와 안전 조건을 모두 확인하기 전 **운영 배포 보류**다.

## 사용자 조작이 필요한 정확한 차단 사항

외부 검증을 위한 추천은 Supabase Free 서울 전용 합성 프로젝트 하나다. 현재 생성/결제 권한이 없고 DB도 없으므로 원격 시험을 실행하지 않았다. 비용·저장 지역·가입/설정·직접 입력할 비공개 환경변수·초기화·Preview 배포 절차를 [설명서의 외부 staging 결정](../transactional/README.md)에 한 번에 정리했다. 비밀값을 채팅에 보내지 않는다. 이 결정은 로컬 구현의 차단 조건으로 사용하지 않았다.
